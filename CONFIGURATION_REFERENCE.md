# Configuration Reference

Tech Context Graph deliberately separates editable configuration from operational state.

## 1. Global workspace registry

This file is created automatically and contains only workspace references chosen by the user.

- Windows: `%APPDATA%\TechContextGraph\workspaces.json`
- Linux: `${XDG_CONFIG_HOME:-~/.config}/tech-context-graph/workspaces.json`
- macOS: `~/Library/Application Support/TechContextGraph/workspaces.json`

Override for testing or portable installations:

```text
TCG_CONFIG_HOME
```

Example:

```json
{
  "version": 1,
  "lastWorkspaceId": "WS-123",
  "recentPaths": ["D:\\TCG\\CompanyCatalog"],
  "workspaces": [
    {
      "id": "WS-123",
      "name": "Company Catalog",
      "path": "D:\\TCG\\CompanyCatalog",
      "createdAt": "2026-07-13T12:00:00Z",
      "lastOpenedAt": "2026-07-13T14:00:00Z"
    }
  ]
}
```

Do not manually add untrusted paths. Prefer `tcg workspace:create` or the interactive UI.

## 2. Workspace marker

File:

```text
tech-context-graph.workspace.json
```

Purpose:

- proves that the folder is a workspace;
- provides stable identity;
- prevents silent use of an arbitrary current directory;
- supports workspace discovery from child folders.

## 3. Editable workspace configuration

File:

```text
tech-context-graph.yaml
```

This is the main human-editable configuration. CLI changes to repository roots are synchronized here and to SQLite.

### `workspace`

Defines identity and internal paths.

```yaml
workspace:
  id: company-catalog
  name: Company Catalog
  paths:
    database: ./.tcg/state.sqlite
    logs: ./.tcg/logs
    graphs: ./tech-graphify-out
    reports: ./context-pack
```

Relative paths are resolved from the workspace folder.

### `ui`

```yaml
ui:
  language: en
  color: auto
  confirm_before_scan: true
  confirm_before_inspection: true
  show_advanced_actions: false
```

### `repository_discovery`

```yaml
repository_discovery:
  default_max_depth: 7
  default_min_confidence: 60
  maximum_directories: 25000
  stop_at_detected_repository: true
  include_unknown_git_repositories: true
  roots:
    - path: D:/Development
      enabled: true
      max_depth: 7
      min_confidence: 60
      role: technology
```

`roots` can be edited manually, but CLI management is safer because it validates the path and updates SQLite.

### `graphify`

```yaml
graphify:
  executable: graphify
  code_only: true
  force_rebuild: false
  query_log_disabled: true
  semantic:
    backend: ollama
    model: null
    mode: deep
```

### `security`

```yaml
security:
  allow_external_llm: false
  block_sensitive_sources: true
  scan_secrets: true
  copy_raw_sources: true
```

### `persistence`

```yaml
persistence:
  driver: sqlite
  file: ./.tcg/state.sqlite
  artifact_storage: filesystem
```

## 4. SQLite operational state

File:

```text
.tcg/state.sqlite
```

Stores:

- configured roots and scan dates;
- detected and accepted repositories;
- technology evidence and confidence;
- Graphify executions;
- graph locations and counts;
- source fingerprints;
- errors and logs;
- graph queries.

Do not edit this file with a text editor.

## 5. Technology catalog

File:

```text
config/technology-catalog.yaml
```

Defines detection markers, package dependencies, categories and ignore profiles. Extend this file when supporting another framework.

## 6. Environment variables

| Variable | Purpose |
|---|---|
| `TCG_WORKSPACE` | Explicit workspace for non-interactive commands |
| `TCG_CONFIG_HOME` | Override the global workspace registry folder |
| `TCG_KIT_ROOT` | Locate the package root during development or tests |

## 7. Configuration priority

Workspace resolution follows this order:

1. `--workspace` or legacy `--root`;
2. `TCG_WORKSPACE`;
3. workspace marker in the current folder or an ancestor;
4. last valid workspace in the global registry;
5. interactive workspace manager.

The current directory is never adopted silently.
